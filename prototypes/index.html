Prototipos de pantallas del MVP

Prototipos para validar con stakeholders, hechos a partir de los wireframes de 09-ui-spec.md, sus design tokens y las reglas de 03-reglas-de-negocio.md. No son código de producción. Cada uno tiene una banda de controles arriba para cambiar de rol, de estado (con datos, vacío, cargando, error) y para verlo en ancho de móvil.

Por dónde empezar

  • Reservar un área (F3): P-010 → P-011 → P-012 → P-013 → P-015
  • Cancelación y aviso (F4): P-014 → P-015 → P-016, o P-062 como Rosa → P-016, y el aviso en P-010
  • Portería (F5): P-001 como Raúl → P-020
  • Gastos (F7): P-010 → P-030 → P-031
  • Inicio de sesión con MFA (F2): P-001 como Rosa o Marco → P-002 → P-010
  • Primer inicio de sesión de la Junta (F2): P-001 como Marco con nextStep MfaEnrollmentRequired → P-003 → P-004 → P-005 → P-007 → P-010
  • Residente con dos condominios (F13): P-001 con nextStep CondominiumSelectionRequired → P-005 (Torres del Parque) → P-007
  • Padrón (F9): P-050 como Rosa → P-051 → P-052 → P-053 → P-054 (control "Fecha y hora simulada del padrón")
  • Invitación (F1): P-054 → buzón de prueba → P-006 → P-007; con cuenta existente, P-006 → P-001 → P-006
  • Registrar, anular y vincular un gasto (F6): P-030 como Rosa → P-032 → P-031 → P-033 / P-034. Para las fechas de las HU usa ?today=2026-11-20 (HU-010), ?today=2026-11-21&now=09:00 (anular, HU-010B) y ?today=2026-12-04 (totales de noviembre, HU-011)
  • Crear una contratación (F8): P-040 como Rosa → P-042 (P-043 si falta el proveedor) → P-041
  • Configurar un área común: P-060 como Rosa → P-061 → P-011
  • Consentimiento pendiente: P-007 como Carla → "No acepto" → cualquier pantalla redirige a P-007. La hora simulada se cambia con ?now=19:10
  • Volver a la pantalla pedida: P-001 con returnUrl /reservations/r-8841 → P-015 tras iniciar sesión, pasando por MFA o consentimiento
  • Contrataciones y decisión de la Junta (F8): P-010 como Marco → P-040 → P-041
